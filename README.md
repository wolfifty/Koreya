# Бот Саши — корейский язык

Воронка-бот на Node.js (Vercel serverless) + Supabase. Логика: приветствие → выбор цели →
ветки с лид-магнитами → приглашение на консультацию. Плюс админка (мини-Mini App) с таблицей
клиентов и рассылками.

## Структура

```
api/
  webhook.js          — основной хендлер Telegram-вебхука (вся воронка)
  admin/
    check.js           — проверка доступа админа
    users.js            — список клиентов
    broadcast.js         — рассылка
  _lib/
    telegram.js          — обёртка над Bot API, HMAC-проверка initData
    supabase.js           — работа с БД
    content.js             — ВСЕ тексты и ссылки бота (правки — сюда)
public/
  admin/index.html    — админка (Mini App)
  images/             — 3 приветственных фото
supabase/schema.sql   — SQL для таблицы users
```

## 1. Supabase

1. Создать проект на supabase.com.
2. В SQL Editor выполнить `supabase/schema.sql`.
3. В Project Settings → API скопировать:
   - `Project URL` → это `SUPABASE_URL`
   - `service_role` key (не anon!) → это `SUPABASE_SERVICE_KEY`

## 2. Deploy на Vercel

1. Залить этот проект в GitHub-репозиторий (файл `.env` в `.gitignore` — не попадёт в git, это ок).
2. Импортировать репозиторий в Vercel.
3. В Project Settings → Environment Variables добавить:

   | Переменная | Значение |
   |---|---|
   | `TELEGRAM_BOT_TOKEN` | токен бота (уже есть в `.env` локально) |
   | `ADMIN_CHAT_IDS` | Telegram user ID через запятую — твой и Сашин (узнать ID можно у бота @userinfobot) |
   | `SUPABASE_URL` | из шага 1 |
   | `SUPABASE_SERVICE_KEY` | из шага 1 |
   | `CLIENT_USERNAME` | `sashaagv` |
   | `SITE_URL` | домен деплоя, например `https://korean-bot.vercel.app` (без слэша на конце) — добавить **после** первого деплоя, когда домен уже известен, затем передеплоить |

4. Deploy.

## 3. Подключить вебхук

После деплоя (и когда известен домен):

```
curl "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook?url=https://<твой-домен>/api/webhook"
```

Проверить: `https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getWebhookInfo`

## 4. Админка

Открывается командой `/admin` в чате с ботом — но **только** для Telegram ID из `ADMIN_CHAT_IDS`
(остальным бот на эту команду ничего не ответит). Бот присылает кнопку «Открыть админку»,
которая открывает Mini App на `/admin`.

Внутри: таб «Клиенты» — таблица (ник / ветка / дата), таб «Рассылка» — фото (необязательно) +
текст (`*жирный*`, `_курсив_`) + кнопка (текст + ссылка, необязательно) + получатели
(все / по ветке / выбранные вручную) → подтверждение → отправка → счётчик успех/ошибка.

## Важно про масштаб рассылок

Рассылка идёт последовательно с небольшой паузой между сообщениями (лимиты Telegram —
~30 сообщений/сек). Функция `broadcast.js` рассчитана на 60 секунд выполнения
(`maxDuration` в `vercel.json`) — этого хватит примерно на 500–800 получателей. Если база
вырастет сильно больше — потребуется вынести рассылку в очередь (например Upstash QStash,
как было сделано в проекте с тестом на архитип) с отправкой батчами. Дай знать, если до этого
дойдёт — добавлю.

- `Для себя — знает алфавит`
